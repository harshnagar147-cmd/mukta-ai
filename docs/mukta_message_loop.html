One message, start to finish

The app has no automatic trigger and no channel of its own — every loop starts and ends with an account manager, and WhatsApp sits entirely outside the system. What the software contributes is the middle: two gates that read shared history before a draft is even offered, a click-to-chat link that opens the message pre-filled instead of asking anyone to copy it, and a queue that a rule — not a click — puts things into.

Why a human still bridges it twice

The app has no WhatsApp Business API connection, so it cannot send a message or read a reply on its own. Sending is now a click-to-chat link (wa.me) — the chat opens with the draft already typed in, so the only manual act left is pressing Send. Logging the reply is unchanged: there is no read access to WhatsApp, so the account manager still types what the client said into "Add feedback" by hand. A real WhatsApp Business API would close that second gap; it needs Meta business verification and per-conversation cost that a course prototype doesn't carry.

Why the gates read history, not a checkbox

The review gate and cooldown gate both query the same two files the bottom half of the loop writes to — a client's own feedback record decides whether they can be asked for a public review, and their own send history decides whether they're due a message at all. Neither can be bypassed by a rushed click, because neither is a click to begin with.
